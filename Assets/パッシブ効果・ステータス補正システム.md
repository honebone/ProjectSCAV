# パッシブ効果・ステータス補正システム

Entity（プレイヤー・敵）、銃、投射物のステータスをインプラント・ソフトウェア・Holdableアイテム・バフ/デバフから補正する仕組みについてまとめる。

## 全体像

パッシブ効果を持つ要素は3種類。すべて `IPassive` を実装する。

| 種類 | データ | Model | 効果が続く期間 |
|---|---|---|---|
| インプラント | `ImplantData` | `ImplantModel` | インプラントスロットに装備している間 |
| Holdableアイテム（道具） | `ToolData` | `ToolModel` | 手に持っている間（`OnHold`〜`OnUnhold`） |
| バフ・デバフ | `BuffData` | `BuffModel` | 効果時間が切れるまで |

```csharp
public interface IPassive
{
    void OnApply(EntityModel owner);   // 効果が付与されたとき
    void OnRemove(EntityModel owner);  // 効果が取り除かれたとき
}
```

`ImplantModel` / `ToolModel` / `BuffModel` はいずれも `IPassive` を実装し、`OnApply`/`OnRemove` の既定実装として「Dataに設定したステータス補正を自動適用する」処理を持つ。**単純なステータス補正だけのパッシブは、C#クラスを新設せずデータアセットの作成だけで完結する。** それ以外の独自効果（イベント購読、投射物生成など）を持たせたい場合のみ、`ImplantModel`/`ToolModel`/`BuffModel` を継承してoverrideする。

`IPassive`インターフェース自体は`OnApply`/`OnRemove`のみで最小限に保っているが、`ImplantModel`/`ToolModel`/`BuffModel`にはそれぞれ`OnTick(deltaTime, owner)`（`BuffModel`は`protected virtual void OnTick(float, EntityModel)`、`ImplantModel`は`public virtual void OnTick(float, EntityModel)`、`ToolModel`は`protected virtual void OnTick(float, EntityModel)`）が用意されており、装備/付与している間毎フレーム呼ばれる。「立ち止まっている間だけ拡散ペナルティが低下する」のような常時条件判定が必要なパッシブはこれをoverrideする（詳細は後述）。

- `ImplantModel.OnTick` は `LoadoutModel.Tick()` が装備中のインプラントに対して毎フレーム呼ぶ。
- `ToolModel.OnTick` は「実際に持っている間（`OnHold`〜`OnUnhold`の間）」だけ呼ばれるようガードされている（`HoldableSlot.Tick`はスロットに入っている間は持ち替えに関わらず毎フレーム呼ばれるため、`ToolModel`内部で`OnApply`〜`OnRemove`の間だけ`OnTick`を呼ぶようにしている）。
- `BuffModel.OnTick` は元から存在し、`EntityModel.TickBuffs()`が毎フレーム呼ぶ（変更なし）。

- `Assets/Scripts/Entity/Loadout/ImplantSlot.cs`

## 作用（EffectAction）

ダメージ・回復・バフ付与など、エンティティに対して働く効果はすべて `EffectAction` として表現し、`EntityModel.Resolve(EffectAction)` の一箇所に集約して解決する。弾丸命中・パッシブ効果によるトリガーなど、発生源によらず同じ経路を通る。

`EffectAction` は継承階層を持たず、単一のクラスが各効果の要素をパラメータとして保持する。初期値（0や空リスト）でない要素だけが解決されるため、1つのインスタンスで「ダメージ＋デバフ付与」のような複合効果も表現できる。

```csharp
public class EffectAction
{
    public EntityModel Source { get; }              // 発生源（環境要因等はnull許容）
    public float DamageAmount { get; }               // 0ならダメージなし
    public DamageTarget DamageTarget { get; }        // HPAndArmor / HPOnly / ArmorOnly
    public float HealAmount { get; }                 // 0なら回復なし
    public HealTarget HealTarget { get; }
    public IReadOnlyList<BuffApplication> Buffs { get; } // 空なら付与なし
}
```

`EntityModel.Resolve()` は `DamageAmount != 0` ならダメージ解決、`HealAmount != 0` なら回復解決、`Buffs` があれば各バフを付与する。これらは独立した条件判定なので同時に成立してよい。

`EntityModel.Damage()` は `private` 化されており、外部から直接ダメージを与えることはできない。必ず `Resolve(EffectAction)` を経由する。

関連ファイル: `Assets/Scripts/Entity/Effect/EffectAction.cs`、`Assets/Scripts/Entity/EntityModel.cs`

### EffectActionData（インスペクターでの作成）

`EffectAction.Source` は実行時にしか決まらないため直接シリアライズできない。`EffectActionData` はSourceを除いたテンプレートとして `[SerializeField]` で構成し、`Create(EntityModel source)` で実際の `EffectAction` を組み立てる。

「リロード完了時に発火する効果」のように、トリガーの中身をコードでなくデータ側で自由に設定したい箇所で使う（例: `AdrenalineInjectorToolData.OnReloadEffect`）。

関連ファイル: `Assets/Scripts/Entity/Effect/EffectActionData.cs`

## ステータス補正（EntityStatModifier / GunStatModifier / PjtlStatModifier / StatModifiers）

`EntityStats` は `MoveSpeed` / `MaxHp` / `MaxArmor` などの `StatValue` を保持する。`StatValue` は `最終値 = (基礎値 + 実数増加量) * 倍率` で計算され、`AddFlat`/`RemoveFlat`（実数）・`AddMultiplier`/`RemoveMultiplier`（割合、+0.2なら20%増）で補正できる。

どのステータスを・実数か割合か・どれだけ補正するかをコードに書かず、インスペクターで設定できるように `EntityStatModifier` を用意した。銃・投射物向けにも同じ形の `GunStatModifier`/`PjtlStatModifier`（対象enumがそれぞれ`GunStatType`/`PjtlStatType`）がある。

```csharp
[System.Serializable]
public struct EntityStatModifier
{
    public EntityStatType Stat;   // 対象ステータス（MoveSpeed, MaxHp, MaxArmor...）
    public ModifierKind Kind;     // Flat（実数）/ Multiplier（割合）
    public float Amount;
}
// GunStatModifier（Stat: GunStatType）、PjtlStatModifier（Stat: PjtlStatType）も同じ形
```

`EntityStatModifier`は`Extensions.ApplyTo`/`RemoveFrom`で`owner.Stats.Get(Stat)`へ`AddFlat`/`AddMultiplier`する（Push型）。`GunStatModifier`/`PjtlStatModifier`は`owner`を`ILoadoutable`にキャストし、`Loadout.PassiveModifiers.AddGunFlat`/`AddGunMultiplier`等を呼ぶ（Pull型、詳細は次節）。3種とも同じ`ApplyTo(owner, stacks)`/`RemoveFrom(owner, stacks)`という呼び出し方に統一されている。

3種をまとめて1つのフィールドで扱えるよう、`StatModifiers`（複合struct）を用意した。`ImplantData` / `ToolData` / `BuffData` はいずれもこの1フィールドをインスペクターで設定できる形で持ち、`Extensions.cs` の拡張メソッドで一括適用・除去する。

```csharp
[System.Serializable]
public struct StatModifiers
{
    public IReadOnlyList<EntityStatModifier> EntityStatModifiers;
    public IReadOnlyList<GunStatModifier> GunStatModifiers;
    public IReadOnlyList<PjtlStatModifier> PjtlStatModifiers;
}

_data.Modifiers.ApplyTo(owner, stacks);   // 内部で3種それぞれのApplyToを呼ぶだけ
_data.Modifiers.RemoveFrom(owner, stacks);
```

**新しく「自身/銃/投射物のステータスを補正するだけ」のインプラント・道具・バフを追加する場合、C#コードは不要。** `ImplantData`/`ToolData`/`BuffData` のアセットを作成し、`Modifiers`（`StatModifiers`）フィールドに補正したいステータス・種類・量を設定するだけでよい（インスペクター上では自身/銃/投射物の3欄が個別に表示される）。

関連ファイル: `Assets/Scripts/Entity/EntityStatModifier.cs`、`Assets/Scripts/Entity/StatModifiers.cs`、`Assets/Scripts/Entity/Loadout/GunStatModifier.cs`（`GunStatModifier`/`PjtlStatModifier`）、`Assets/Scripts/Entity/EntityStats.cs`（`EntityStatType` 列挙体と `Get()` アクセサ）、`Assets/Scripts/Extensions.cs`

## 銃・投射物のステータス補正（Pull型）

銃のマガジン容量・リロード速度・拡散ペナルティや、投射物の弾速・貫通・ダメージも同様に `StatValue` で管理されている（`GunStats` / `PjtlStats`）。ただし自身のステータスと違い、銃は複数所持・持ち替えが起こるため、装備時に個々の `GunModel` へ直接補正を書き込む方式（Push型）だと「装備後に入手した銃」に補正が反映されない問題がある。

そこで銃・投射物の補正は **Pull型** を採用した。`LoadoutModel` が `PassiveModifierSet` を保持し、装備中パッシブはここへ補正を登録するだけにする。`GunModel` は発射・リロードなど実際に値を使う瞬間に毎回 `PassiveModifierSet` を参照して合成する（`GunStats`/`PjtlStats` 自体は書き換えない）。これにより武器の持ち替え・新規入手による反映漏れが構造的に起きない。

```csharp
public enum GunStatType { MagCap, ReloadTime, FireRate, SpreadPenalty_Move, SpreadPenalty_Fire, MaxSpreadPenalty_fire, SpreadLoss }
public enum PjtlStatType { BulletSpeed, BulletLifetime, Penetration, Damage }

public class PassiveModifierSet
{
    public void AddGunFlat(GunStatType type, float amount);
    public void AddGunMultiplier(GunStatType type, float amount);
    public float ApplyGun(GunStatType type, float baseValue); // (base+flat)*(1+multiplier)
    // Pjtl側も同様
}
```

`LoadoutModel.PassiveModifiers` として公開され、`GunModel` 内の各所（`TryFire`/`Tick`/`Reload`等）がここを参照して最終値を算出する。

関連ファイル: `Assets/Scripts/Entity/Loadout/PassiveModifierSet.cs`、`Assets/Scripts/Item/Equippable/Holdable/Gun/GunModel.cs`、`Assets/Scripts/Entity/IProjectileSpawner.cs`（`PjtlSnapshot.From(stats, mods)`）

`GunStatModifier`/`PjtlStatModifier`（インスペクターでの設定方法）は前節「ステータス補正」を参照。`ImplantData`/`ToolData`/`BuffData`の`Modifiers`（`StatModifiers`）フィールドから`EntityStatModifier`と並べて設定できる。

## 弾丸命中時のダメージ・デバフ（OnHitBuffs）

`PjtlData`/`PjtlStats`/`PjtlSnapshot` に `Damage`（`StatValue`）を持たせ、`Projectile` が命中したエンティティに対して `EffectAction` を発行する。命中時に「ダメージ＋デバフ付与」を同時に行いたい場合（酸弾等）は、`PjtlData` に `OnHitBuffs`（`BuffApplication[]`）を設定するだけでよい。`EffectActionData`と同じ`BuffApplication`型をそのまま流用しており、`PjtlStats`/`PjtlSnapshot`を経由してそのまま`Projectile`まで転送される（パッシブ補正の対象ではなく弾種固有のデータ）。

```csharp
target.Resolve(new EffectAction(_fireParams.Source, damageAmount: _fireParams.Snapshot.Damage,
    damageTarget: DamageTarget.HPAndArmor, buffs: _fireParams.Snapshot.OnHitBuffs));
```

`_fireParams.Source` は発射者（`EntityModel`）で、`FireParams` に保持している。貫通する弾の場合、命中したエンティティ全員に同じ`OnHitBuffs`が付与される。

関連ファイル: `Assets/Scripts/Entity/Projectile.cs`、`Assets/Scripts/Entity/PjtlData.cs`

## 命中時のEffectAction動的補正（IProjectileHitModifier）

`PassiveModifierSet`のスカラー加算（Pull型）では、「命中した個々のターゲットの状態」「その弾自身の飛翔距離」のような**命中の瞬間にしか分からない値**を使った補正は表現できない。この種の効果（例：HPが一定割合以下の敵に追加デバフ、飛翔距離に応じてダメージ増加）は`IProjectileHitModifier`で実現する。

```csharp
public interface IProjectileHitModifier
{
    EffectAction Modify(EffectAction baseAction, ProjectileHitContext context);
}
```

`ProjectileHitContext`は命中の瞬間の状態（`Target`/`Source`/`DistanceTraveled`/`TimeAlive`/`HitIndex`/`Snapshot`）を持つ読み取り専用データ。`PassiveModifierSet`に`AddHitModifier`/`RemoveHitModifier`で自己登録し（`BuffModel : IPassive`と同様、実装クラス自身が`IProjectileHitModifier`を実装する形を想定）、`Projectile`が命中のたびに`PassiveModifiers.ApplyHitModifiers(baseAction, context)`を通してから`EntityModel.Resolve()`する。`Projectile`は`Init()`時の発射地点からの距離・生成からの経過時間を追跡し、`ProjectileHitContext`に渡す。

### EffectActionModifier（Modify実装を書きやすくするstruct）

`EffectAction`は不変（コンストラクタでしか値を作れない）なため、`Modify()`内で1箇所だけ値を変えたい場合でも本来はコンストラクタの全引数をコピーし直す必要がある。この手間を減らすため`EffectActionModifier`（ダメージ・回復の実数/割合補正＋追加バフをまとめたstruct）を用意した。

```csharp
public struct EffectActionModifier
{
    public float DamageFlat;
    public float DamageMultiplier;   // +0.2なら20%増（PassiveModifierSet等と同じ規約）
    public float HealFlat;
    public float HealMultiplier;
    public IReadOnlyList<BuffApplication> AdditionalBuffs;

    public EffectAction Apply(EffectAction baseAction); // (base+flat)*(1+multiplier)で合成した新しいEffectActionを返す
}
```

`Modify()`実装例:
```csharp
// 飛翔距離に応じてダメージ増加
public EffectAction Modify(EffectAction baseAction, ProjectileHitContext context)
{
    return new EffectActionModifier(damageFlat: context.DistanceTraveled * _damagePerDistance).Apply(baseAction);
}

// HP割合条件のデバフ
public EffectAction Modify(EffectAction baseAction, ProjectileHitContext context)
{
    float hpRatio = context.Target.Stats.MaxHp.Value > 0 ? context.Target.Hp / context.Target.Stats.MaxHp.Value : 0f;
    if (hpRatio > _threshold) return baseAction;
    return new EffectActionModifier(additionalBuffs: new[] { _extraDebuff }).Apply(baseAction);
}
```
`[System.Serializable]`にしているため、将来的に「常に距離ダメージ+Xを付与する」のようなImplant/ToolのデータをSerializeFieldとして直接設定する用途にも転用できる。`DamageTarget`/`HealTarget`自体の上書きは非対応（必要になった時点で拡張する）。

関連ファイル: `Assets/Scripts/Entity/IProjectileHitModifier.cs`、`Assets/Scripts/Entity/ProjectileHitContext.cs`、`Assets/Scripts/Entity/Effect/EffectActionModifier.cs`、`Assets/Scripts/Entity/Loadout/PassiveModifierSet.cs`、`Assets/Scripts/Entity/Projectile.cs`

## バフ・デバフ（BuffData / BuffModel）

`BuffData`（ScriptableObject）は効果時間・重ねがけポリシー・ステータス補正を持つ。`BuffModel`（実行時インスタンス）は残り時間とスタック数の管理に専念し、実際の効果は `OnApply`/`OnRemove`/`OnTick`（いずれも仮想メソッド）に委ねる。既定実装は「`Modifiers`（`StatModifiers`）を適用」のみなので、多くのバフはBuffDataアセットの作成だけで表現できる。

```csharp
public enum StackPolicy
{
    Refresh,        // 再付与時は残り時間だけ延長（スタックは増えない）
    StackDuration,  // 再付与のたびに独立したタイマーを持つ別インスタンスとして積み増す
    StackMagnitude, // 同一インスタンスのスタック数を増やし、補正量・を倍加する
}
```

例:
- スピードブースト: `Multiplier` で `MoveSpeed` を補正、`StackPolicy = Refresh`

独自効果（ステータス補正以外）を持たせたいバフは、`BuffData`/`BuffModel` をそれぞれ継承し `CreateModel()` をoverrideする（`ImplantData`/`ImplantModel` と同じパターン）。

`EntityModel` はバフのリストを基底クラス自身が保持する（`ILoadoutable` はプレイヤー専用だが、バフは敵にも掛かるため）。`Tick()` 内で毎フレーム `TickBuffs()` を呼び、期限切れのバフを自動的に除去する。

関連ファイル: `Assets/Scripts/Entity/Effect/BuffData.cs` / `BuffModel.cs`、`Assets/Scripts/Entity/EntityModel.cs`

## パッシブ効果の付与経路

### インプラント
`LoadoutModel.TryEquipImplant(index, implant, owner)` → `ImplantSlot.TryEquip()` → `implant.OnApply(owner)`

### Holdableアイテム（道具）
`ToolModel` は `OnHold(owner)`/`OnUnhold(owner)` のタイミングで自身の `OnApply`/`OnRemove` を呼ぶ。`LoadoutModel.SwitchSlot()` が武器・道具の持ち替え時に呼び出す。

### バフ
`EntityModel.Resolve(EffectAction)` の `Buffs` を経由して `ResolveBuff()` が付与する。

### 自身への作用トリガー（イベント駆動のパッシブ）
「リロード完了で自身にバフを付与する」のような、装備しているだけでなく特定のイベントで発動するパッシブは、`OnApply`/`OnRemove` 内でイベント購読・解除を行う。武器の持ち替えに影響されないよう、個々の `GunModel` ではなく `LoadoutModel` が公開する集約イベント（`OnAnyGunFired`/`OnAnyGunReloadCompleted`）を購読する。これは `LoadoutModel` がロードアウトに銃が追加されるたびに内部で購読を張り替えているため、パッシブ側は装備時に一度購読するだけでよい。

実装例: `AdrenalineInjectorToolModel`（`Assets/Scripts/Item/Equippable/Holdable/Gear/Tool/`）— リロード完了イベントを購読し、`EffectActionData` から組み立てた効果を自身に発動する。

## 新しいパッシブ効果を追加する手順

1. **自身・銃・投射物のステータスを補正するだけ** → `ImplantData`/`ToolData`/`BuffData` のアセットを作成し `Modifiers`（`StatModifiers`。自身/銃/投射物の3欄がまとまっている）を設定するだけ（コード不要）
2. **特定イベントで効果を発動したい**（例: 撃破時にHP回復、リロード時にバフ付与、被弾時に一時的なバフ付与、持ち替え直後だけのバフ付与）→ `ImplantModel`/`ToolModel`/`BuffModel` を継承し、`OnApply`/`OnRemove` でイベント購読/解除（`LoadoutModel.OnAnyGunFired`/`OnAnyGunReloadCompleted`/`OnActiveItemChanged`、`EntityModel.OnHPDamaged`/`OnArmorDamaged`等）、ハンドラ内で `owner.Resolve(new EffectAction(...))` または `EffectActionData.Create(owner)` を呼ぶ。「一定時間だけ」の効果は`BuffData`（`Modifiers`に銃・投射物側の補正を設定）を`BuffApplication`として付与すれば期限切れ処理も含めて既存の仕組みに乗る
3. **投射物を生成したい**（例: 被弾時に周囲へミサイル）→ 上記のイベントハンドラ内で `owner.SpawnProjectile(fireParams)` を呼ぶ
4. **弾丸命中時にデバフを付与したい**（酸弾等）→ `PjtlData` の `OnHitBuffs` を設定するだけ（コード不要）
5. **常時Tickでの条件判定が必要**（例: 立ち止まっている間だけ拡散ペナルティ低下、マガジン最後の1発はダメージ増加）→ `ImplantModel`/`ToolModel` を継承し `OnTick(deltaTime, owner)` をoverrideする。条件が成立している間だけ `(owner as ILoadoutable)?.Loadout.PassiveModifiers.AddGunFlat(...)`等を呼び、条件が外れたら対称に`Remove`する（トグル方式）。「発射で消費する一回だけのボーナス」は`OnTick`での蓄積＋`LoadoutModel.OnAnyGunFired`購読でのリセットを組み合わせる
6. **命中したターゲットの状態・弾自身の飛翔距離等に応じて命中時の効果を補正したい**（例: HPが一定割合以下の敵に追加デバフ、飛翔距離に応じてダメージ増加）→ 対象のクラス（Implant/Tool/Buffのサブクラス）に `IProjectileHitModifier` を実装し、`OnApply`/`OnRemove` で `Loadout.PassiveModifiers.AddHitModifier(this)`/`RemoveHitModifier(this)` を呼ぶ
